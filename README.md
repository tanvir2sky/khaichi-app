# আমি খেয়েছি

A Bangla-first share-card web app. Users tick off what they've eaten or visited and get a brag card to post on Facebook. There are four collections:

| Route | Collection | Items | Levels |
|---|---|---|---|
| `/` | ৬৪ জেলার বিখ্যাত খাবার (map) | 64 districts | খেয়েছি / জেলায় গিয়ে খেয়েছি / ভক্ত |
| `/pitha/` | পিঠা (grid) | 38 | খেয়েছি / নিজে বানিয়েছি / প্রতি শীতে খাই |
| `/fol/` | দেশি ফল (grid) | 51 | খেয়েছি / গাছ থেকে পেড়ে খেয়েছি / নিজের গাছ আছে |
| `/world/` | আমি ঘুরেছি: বিশ্ব (map) | 194 countries | ট্রানজিট / ঘুরেছি / থেকেছি |

Other routes:
- `/district/<id>/`: 64 SEO pages, one per district.
- `/leaderboard/`: the district leaderboard (optional, needs Supabase).

The growth plan is in [docs/LAUNCH-PLAYBOOK.md](docs/LAUNCH-PLAYBOOK.md). Food entries that need checking before launch are in [docs/DATA-REVIEW.md](docs/DATA-REVIEW.md).

## Quick start

```bash
npm install
cp .env.example .env        # set VITE_SITE_URL at minimum
npm run dev                 # http://localhost:5173
```

## Build and deploy

```bash
npm run build      # typecheck, vite build, then prerender 69 HTML pages + sitemap.xml + robots.txt
npm run preview    # serves dist/ on http://localhost:4173
```

`dist/` is a fully static site. It doesn't need a server, so a traffic spike costs nothing.

**Cloudflare Pages:** set the build command to `npm run build` and the output directory to `dist`, and add `VITE_SITE_URL` (plus the optional variables below) as environment variables. There's no `404.html`, so unknown paths fall back to the SPA. Vercel and Netlify work the same way.

`npm run build` **fails if `VITE_SITE_URL` is missing**. That's deliberate: canonical URLs, OG tags and the sitemap all depend on it.

## Environment

| Variable | Required | Purpose |
|---|---|---|
| `VITE_SITE_URL` | yes | Public URL, without a trailing slash. Used for canonical links, OG tags, the sitemap and share links. |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | no | Turn on the district leaderboard. Without them the leaderboard UI is hidden. |
| `VITE_TURNSTILE_SITE_KEY` | no | Cloudflare Turnstile captcha for anonymous sign-in (anti-spam). |
| `VITE_POSTHOG_KEY`, `VITE_POSTHOG_HOST` | no | Analytics via `sendBeacon`, with no SDK bundled. |
| `VITE_FEEDBACK_URL` | no | Link for "তথ্যে ভুল? ধরিয়ে দিন" (for example a Google Form). |

## Leaderboard setup (Supabase)

1. Create a Supabase project.
2. In **Authentication → Sign In / Providers**, enable **anonymous sign-ins**.
3. Run [supabase/migrations/001_init.sql](supabase/migrations/001_init.sql) in the SQL editor. It's generated from the app's data by `npm run gen:sql`; regenerate it whenever collection sizes change.
4. Optional, recommended: in **Authentication → Attack Protection**, enable CAPTCHA with Cloudflare Turnstile, and set `VITE_TURNSTILE_SITE_KEY`.
5. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, then rebuild.

How it works:
- Each device signs in anonymously and upserts one row per collection: home district, score, count, and the encoded levels.
- Row-level security lets users read and write only their own row.
- Public data comes only from two `security definer` functions, `leaderboard()` and `leaderboard_total()`.
- Districts are ranked by a Bayesian average (C = 20), and a district only appears once it has at least 5 players.
- The Supabase SDK is lazy-loaded, so it never adds to the first page load.

> ⚠️ The SQL and the client have **not been run against a live Supabase project** yet. Before you announce the leaderboard, test the join and leaderboard flow once on your own project.

## Data

| File | What | How to update |
|---|---|---|
| `src/data/districts.ts` | 64 districts in a **frozen order** | Append only. Share links encode one level per item in this order, and `tests/data.test.ts` guards it. |
| `research/*.json` | Researched foods, pitha and fruits, with sources | Edit by hand, then run `npm run import:data && npm run review`. |
| `src/data/food64.json`, `pitha.json`, `fol.json` | Generated app data | Don't edit; regenerated by `import:data`. |
| `src/data/bdMap.json` | District SVG paths, centroids, neighbours (geoBoundaries, CC BY 3.0 IGO) | `npm run build:map` |
| `src/data/worldMap.json`, `countries.json` | World map (Natural Earth, public domain) and 194 countries | `npm run build:world` |
| `public/og/*.png` | 1200×630 link-preview images | `npm run og` |

## How the share card works

Cards are rendered in the browser (`src/components/ShareCard.tsx` → `src/lib/capture.ts`, using modern-screenshot) so that Chrome's own text shaper handles Bangla conjuncts. Server-side renderers such as Satori and @vercel/og break যুক্তাক্ষর.

modern-screenshot freezes every element's live width. Mark content-sized boxes with `data-fit` so their text doesn't overflow in the capture, and leave single-line text `nowrap` (the card default).

Sharing goes through one file, `src/lib/share.ts`, in this order: Web Share with the image file, then download, then copying the link. In the Facebook/Messenger in-app browser the card is also shown as an `<img>` that people can long-press to save. A future Capacitor (Android) build only needs to swap `share.ts`.
